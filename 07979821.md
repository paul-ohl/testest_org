# Micro-service architecture

In a micro-service architecture, each separate service of a software system is
handled by a different node.

For example, in a streaming service, the authentication, catalog handling, and
video streaming services would be handled by separate programs that all run
concurrently.

The only centralized element of a micro-service architecture is a load-balancer
that redirects requests to the correct micro-service, but that isn't always the
case, such as for [distributed systems](a9521c47).

## Pros

* **Reliability**: A micro-service architecture helps maintaining the
  [Integrity](952ca7af) of the system because the whole system is generally not
  dependent on a single point of failure, therefore the system is resilient in
  case of a node failing.
* **Computing-power**: Each node adds their computing power to the whole, making it
  easier to have a very powerful overall system.
* **Scalability**: Micro-services are generally built to be stateless, meaning that
  they can easily be parallelized and allow the system to scale only the parts
  that need scaling, and not every single piece of the program.

## Cons

* **Added complexity**: It's much harder to write and maintain a micro-service
  architecture, not to mention that it's overkill for most situations.
* Heavy reliance on network: This is also the case for any system built for the
  web, but since each node of a micro-service has to interact with others
  through the network, the whole system becomes depend on that ability to
  communicate through a medium.

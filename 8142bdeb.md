# Aspects and layers of a software system

When building a software system, there are aspects of the architecture that the
user "cares" about, what they will interact with, and other aspects which they
will hardly ever interact nor care about.

This differenciation is between the "Application" and the "Implementation".

Then there are two other aspects: The functional and non-functional aspects.

Generally, functional vs non-functional distinguishes between *what* the system
does and *how* it does it.

This creates a table with "Functional | Non-functional" as one dimension and
"Application | Implementation" as the other.

[Integrity](952ca7af) is a major aspect of Non-functional implementation. The
user generally doesn't learn about *how* their data is secure and works the way
they expect.

## Example: A smart-phone

Application and functional would be taking photos, making calls, etc.

Application and non-functional would be having a great UX/UI and a performant
phone.

Implementation and functional would be saving the photos locally or on the
cloud, making a connection to the nearest mobile tower.

Implementation and non-functional would be to store the photos efficiently,
saving energy and ensure user privacy.
